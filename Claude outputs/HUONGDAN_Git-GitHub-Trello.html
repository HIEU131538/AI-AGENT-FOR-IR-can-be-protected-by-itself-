Phần 0

Git, GitHub và Trello khác nhau thế nào

Git là phần mềm cài trên máy từng người. Nó chụp lại trạng thái code mỗi lần mình bảo nó (mỗi lần chụp gọi là một commit), nên luôn quay lại được bản cũ và biết ai sửa dòng nào. Git cho phép mở nhánh: một bản sao riêng để thử nghiệm mà không làm hỏng bản chính.

GitHub là trang web giữ một bản Git chung cho cả nhóm (gọi là repo). Mỗi người đẩy (push) code của mình lên đó và kéo (pull) code của người khác về. Muốn đưa nhánh của mình vào bản chính thì mở một Pull Request để trưởng nhóm xem trước rồi mới gộp.

Trello không liên quan tới code. Nó là bảng công việc kiểu dán giấy nhớ: mỗi việc là một thẻ, thẻ đi qua các cột từ "chưa ai làm" tới "xong". Thầy nhìn board là biết nhóm đang ở đâu, ai đang làm gì, việc nào bị kẹt.

Nối ba thứ lại: một thẻ Trello = một nhánh Git = một Pull Request. Giữ đúng quy tắc này thì board và repo luôn khớp nhau.

Phần 2

P1 dựng repo GitHub (làm một lần)

Chỉ P1khoảng 45 phút

  1. Tạo tài khoản GitHub

    Vào github.com/signup, nên đăng ký bằng email trường để bước sau xác minh sinh viên dễ hơn. Cả 5 người đều tạo tài khoản và gửi username cho P1.

  2. Xin GitHub Student Developer Pack (nên làm ngay)

    Vào education.github.com/pack, xác minh là sinh viên. Gói này cho tài khoản GitHub Pro miễn phí. Lý do cần: GitHub Free không cho khoá nhánh main trên repo private, còn GitHub Pro thì cho. Duyệt có thể mất vài ngày; trong lúc chờ cả nhóm vẫn làm việc bình thường theo quy ước ở Phần 5.

  3. Cài Git trên máy mình

    Làm giống Phần 3 bên dưới, rồi quay lại đây.

  4. Tạo repo trống trên GitHub

    Bấm dấu + góc trên phải → New repository. Tên: edgeguard-ai. Chọn Private. Không tick "Add a README", không chọn .gitignore hay license, vì mình sẽ đẩy khung có sẵn lên. Bấm Create repository và giữ trang đó mở để lấy đường link https://github.com/<username>/edgeguard-ai.git.

  5. Chuẩn bị thư mục trên máy

    Giải nén edgeguard-ai_khung-repo.zip, ví dụ vào D:\edgeguard-ai. Chép code nhánh thị giác cũ (edgeguard-vision) vào thư mục con vision/. Không chép thư mục dataset, runs/, file .pt; file .gitignore trong khung đã chặn sẵn nhưng để ngoài vẫn gọn hơn.

  6. Đẩy lần đầu

    Mở thư mục D:\edgeguard-ai trong VS Code → menu Terminal → New Terminal, rồi chạy từng dòng:

    git init -b main
git add .
git status                 # ĐỌC KỸ: không được có dataset, .pt, .env
git commit -m "Khởi tạo khung dự án EdgeGuard-AI"
git remote add origin https://github.com/<username>/edgeguard-ai.git
git push -u origin main

    Lần push đầu, Windows sẽ bật cửa sổ đăng nhập GitHub qua trình duyệt. Đăng nhập một lần là xong, những lần sau không hỏi nữa. Tải lại trang repo trên GitHub sẽ thấy các thư mục.

  7. Mời 4 bạn vào repo

    Trên trang repo: Settings → Collaborators → Add people, nhập username từng bạn. Mỗi bạn vào email hoặc thông báo GitHub bấm Accept. Có thể mời cả thầy nếu thầy muốn xem code.

  8. Khoá nhánh main (sau khi có GitHub Pro)

    Settings → Branches → Add branch protection rule (hoặc Rules → Rulesets ở giao diện mới). Tên nhánh: main. Tick Require a pull request before merging và Require approvals = 1. Từ đó không ai đẩy thẳng vào main được, mọi thay đổi phải qua P1 duyệt.

  9. Điền link vào README

    Sau khi có board Trello (Phần 7) và thư mục Drive chứa dữ liệu, dán hai link vào cuối README.md. Đây là việc đầu tiên để P1 tự tập vòng làm việc ở Phần 4.

Phần 3

Mỗi thành viên cài Git và lấy code về (làm một lần)

Cả 5 ngườikhoảng 20 phút

  1. Cài VS Code và Git

    Cài VS Code trước. Sau đó tải Git for Windows ở git-scm.com/download/win. Khi cài, bấm Next gần hết, chỉ đổi hai chỗ: màn hình default editor chọn Use Visual Studio Code; màn hình initial branch name chọn Override và gõ main. Các màn hình khác giữ mặc định (có cả Git Credential Manager để đăng nhập GitHub).

  2. Khai báo tên và email

    Mở VS Code → Terminal → New Terminal, chạy (thay bằng tên thật và đúng email tài khoản GitHub):

    git --version                 # có số phiên bản là cài được
git config --global user.name "Nguyen Van A"
git config --global user.email "email-github@gmail.com"

    Tên này hiện trên mọi commit, nên P1 và thầy biết ai làm gì.

  3. Nhận lời mời và clone repo

    Chấp nhận lời mời của P1 trên GitHub. Chọn chỗ để code, ví dụ D:\, rồi chạy:

    cd D:\
git clone https://github.com/<username-P1>/edgeguard-ai.git
cd edgeguard-ai
code .                        # mở thư mục trong VS Code

    clone là tải cả repo kèm lịch sử về máy. Chỉ làm một lần; từ đó về sau dùng git pull để cập nhật.

  4. Tạo file .env riêng

    Sao chép .env.example thành .env rồi điền token thật của mình (Splunk HEC, AbuseIPDB...). File .env đã bị .gitignore chặn nên không bao giờ lên GitHub.

Phần 4

Vòng làm việc cho mỗi thẻ

Cả 5 người, lặp lại mãi

Đây là phần quan trọng nhất. Ví dụ bạn P2 nhận thẻ "Cấu hình HEC nhận alert thị giác":

  1. Trên Trello: nhận thẻ

    Kéo thẻ từ Backlog sang Đang làm, bấm vào thẻ → Members → chọn tên mình.

  2. Lấy code mới nhất và mở nhánh

    git switch main
git pull
git switch -c siem/hec-alert-thi-giac

    Lệnh cuối tạo nhánh mới và chuyển sang nhánh đó. Từ đây mọi thứ mình sửa chỉ nằm trên nhánh này.

  3. Làm việc, rồi commit từng bước nhỏ

    git status                               # xem file nào đã đổi
git add siem/splunk/inputs.conf          # chọn file đưa vào commit
git commit -m "siem: thêm cấu hình HEC nhận alert thị giác"

    Commit thường xuyên, mỗi commit một việc. git add . đưa mọi file đã đổi vào, chỉ dùng khi đã đọc git status và chắc không có file lạ. VS Code cũng làm được việc này ở tab Source Control (biểu tượng nhánh cây bên trái): bấm dấu + cạnh file, gõ message, bấm Commit.

  4. Đẩy nhánh lên GitHub

    git push -u origin siem/hec-alert-thi-giac   # lần đầu của nhánh
git push                                    # những lần sau

    Nên push ít nhất cuối mỗi buổi làm, kể cả khi chưa xong, để máy hỏng cũng không mất việc.

  5. Mở Pull Request

    Lên trang repo, GitHub hiện nút Compare & pull request. Bấm vào, điền mẫu có sẵn (link thẻ Trello, làm gì, kiểm thử thế nào), bên phải chọn Reviewers → P1, bấm Create pull request. Chuyển thẻ Trello sang Chờ review.

  6. P1 duyệt và gộp

    P1 mở tab Files changed, đọc, bình luận nếu cần sửa (người làm sửa trên cùng nhánh, commit, push là PR tự cập nhật). Ổn thì bấm Merge pull request → Confirm, rồi Delete branch. P1 chuyển thẻ sang Xong.

  7. Dọn máy và nhận thẻ mới

    git switch main
git pull
git branch -d siem/hec-alert-thi-giac

    Quay lại bước 1 với thẻ tiếp theo.

Phần 6

Khi gặp sự cố

  1. Push bị từ chối: "rejected … fetch first"

    Có người đã đẩy lên nhánh đó trước mình. Chạy git pull rồi git push lại.

  2. Xung đột (conflict)

    Hai người sửa cùng một đoạn trong cùng file. Git đánh dấu trong file như sau:

    <<<<<<< HEAD
severity_id: 4          # bản của mình
=======
severity_id: 5          # bản của người khác
>>>>>>> main

    Mở file trong VS Code, bấm Accept Current / Accept Incoming / Accept Both hoặc tự sửa cho đúng, xoá hết các dòng đánh dấu. Sau đó git add <file> và git commit. Không chắc bản nào đúng thì hỏi người kia, đừng đoán. Chia thư mục theo nhóm đã giảm gần hết xung đột; file dùng chung như schema alert thì báo nhau trước khi sửa.

  3. Lỡ sửa trên main thay vì nhánh riêng (chưa commit)

    Chạy git switch -c <tên-nhánh-mới>. Các thay đổi chưa commit đi theo sang nhánh mới, main vẫn sạch.

  4. Muốn bỏ hết thay đổi chưa commit của một file

    git restore <file>. Lệnh này xoá thay đổi thật, không lấy lại được, nên đọc kỹ tên file trước khi chạy.

  5. Lỡ commit token hoặc mật khẩu

    Báo P1 ngay và thu hồi, tạo lại token đó (trong Splunk, AbuseIPDB, BotFather...). Xoá file bằng một commit mới là không đủ, vì lịch sử Git vẫn giữ bản cũ và ai clone repo cũng xem lại được.

  6. Lỡ commit file lớn, push bị chặn

    Nếu file lớn nằm ở commit cuối cùng và chưa push thành công: chạy git reset --soft HEAD~1 (huỷ commit cuối, giữ nguyên file trên máy), rồi git restore --staged <file-lớn>, thêm đường dẫn file đó vào .gitignore, rồi commit lại. Làm không được thì dừng lại hỏi P1, đừng thử lệnh lạ trên mạng.

    Mỗi thẻ nên gói trong 2–5 ngày. Việc to hơn thì tách thành nhiều thẻ hoặc dùng Checklist trong thẻ.

  5. Mời thành viên

    Trong board bấm Share, nhập email 4 bạn và thầy, hoặc tạo link mời gửi vào nhóm chat. Tắt link mời sau khi mọi người đã vào.

  6. Nối Trello với GitHub

    Trong board: Power-Ups → tìm "GitHub" → Add, bấm biểu tượng bánh răng → Authorize Account và đăng nhập GitHub. Sau đó trong mỗi thẻ có nút GitHub để gắn Pull Request, nhánh hoặc commit; thẻ hiện trạng thái PR (đang mở, đã merge). Mỗi người muốn gắn PR cần tự Authorize một lần bằng tài khoản GitHub của mình.

Phần 8

Thẻ khởi đầu cho Backlog

Lấy từ kế hoạch đề tài hiện tại. P1 tạo các thẻ này rồi xếp thứ tự; thẻ in nghiêng có thể gắn nhãn Ai cũng nhận được.

Chung, làm trước tiên

  • Cả nhóm cài Git, clone repo, commit thử một dòng tên mình vào docs/thanh-vien.md qua Pull Request (bài tập làm quen, mỗi người một thẻ)
  • Chốt ý nghĩa từng mức severity_id (1–5) và confidence_id (1–3) giữa P1 và nhóm SIEM
  • Chốt quy ước device_id chung trong asset_inventory.yaml và đồng bộ NTP giữa camera và Gateway
  • Chốt danh sách cột features của alert (B) trước khi ai train

Thị giác, P1

  • Sửa code trỏ yolo11n.pt sang yolo11s và train lại 4 patch cổ điển
  • Viết hàm suy giảm theo 4 mức (nhiễu, nén JPEG, mờ chuyển động, méo phối cảnh, đổi sáng) và chạy Bảng F
  • Train Logistic Regression trên C/D/E thay cho heuristic tạm
  • Chạy benchmark B1 → B3 và xuất 6 bảng A–F
  • Quyết định giữ hay bỏ PS-GAN

SIEM, P2 và P3

  • Cài Sysmon trên Gateway Windows Server, lưu file cấu hình XML vào siem/sysmon/
  • Cài Splunk và Universal Forwarder, đẩy log Sysmon về Splunk
  • Mở HEC nhận alert thị giác (A) dạng JSON, token để trong .env
  • Viết correlation search (Sigma chuyển sang SPL) sinh alert (B) đúng hợp đồng dữ liệu
  • Dashboard Splunk hiển thị alert hai nhánh và kết quả ticket

Dataset và Demo, P4 và P5

  • Thu ảnh người một mình và nhiều người, dựng bộ composite sạch / có patch, ghi manifest.csv
  • Thu dữ liệu telemetry cho Pre-filter: log nền bình thường và log khi chạy Atomic Red Team, gán nhãn, làm sạch
  • Viết kịch bản demo A, B, C từng giây: ai làm gì, alert nào nổ, màn hình nào chiếu
  • Quay video dự phòng cho cả ba demo
  • Dựng bộ 30–50 kịch bản sự cố có đáp án để chấm AI Agent

Làm sau thị giác (P1, người rảnh hỗ trợ)

  • ML Pre-filter: viết extract_features(), bake-off Random Forest và LightGBM, chạy shadow mode
  • Chuyển Agent cũ sang nhận ticket, nạp MITRE ATLAS vào RAG
  • Script sinh tải cho bảng chịu tải bật/tắt Pre-filter
